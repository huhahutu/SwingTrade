
# 要件定義書：フェーズ2 - Dapr基盤導入とマイクロサービス化準備

## 1. 目的・概要

現在のPython (FastAPI) ベースの自動売買プロトタイプ（フェーズ1）に対し、Dapr (Distributed Application Runtime) を導入してアーキテクチャの拡張を行います 。

Daprにより状態管理や秘密情報を抽象化し、将来的なRust (Axum) や SvelteKit への「多言語化（ポリグロット）基盤」を整えるとともに 、mTLSによるサービス間通信の自動暗号化などのセキュリティ強化を実現します 。

---

## 2. システム環境および技術スタック

* **メインエディタ / AIエージェント**: Antigravity 


* **主要言語 / フレームワーク**: Python (FastAPI) 


* **共通ランタイム基盤**: Dapr 


* **コード品質・静的解析**:
* Formatter / Linter: Ruff 


* 型チェック: mypy (Strict モード) 


---

## 3. 実装機能要件（Dapr基盤対応）

### ① Daprコンポーネントの導入と抽象化

* **要件**: プロジェクトにDaprを組み込み、状態管理や秘密情報の抽象化を行える基盤を構築する 。

* **詳細**:
* Dapr Sidecar を介してFastAPIアプリケーションが起動・通信できるように構成を設定する 。


* 将来の Rust や SvelteKit 等の異種言語サービス追加を見据えた構成・コンポーネント設定ファイル（YAML）を作成する 。





### ② 秘密情報管理（Dapr Secrets API）の実装

* **要件**: 機密情報を環境変数からの直接参照から切り離し、Dapr Secrets API 経由で安全に読み込む 。


* **対象情報**:
* SBI証券等のAPIキー・認証情報 
* Gemini APIキー 
* **詳細**:
* Dapr Secret Store コンポーネントの設定ファイルを作成する 。
* Pythonコード内の機密情報取得処理を、Dapr Secrets API呼出しへ変更する 。

### ③ 状態管理（Dapr State Management API）の組み込み

* **要件**: アプリケーション内の状態データ（注文ステータスや一時的な取引コンテキスト等）をDapr State Store経由で保存・取得できるようにする 。


* **詳細**: Dapr State Store コンポーネント（例: Redis/Local State Store等）を定義し、状態アクセスロジックを抽象化する 。


### ④ セキュリティ設定（mTLS通信暗号化）

* 
**要件**: Daprを介したサービス間通信に対し、mTLS (Mutual TLS) を適用する 。


* 
**詳細**: サービス間通信が自動的に暗号化されるよう、Daprのセキュリティ設定を反映させる 。

## 4. コーディング規約および品質要件

* 
**型安全性の確保**: すべての関数およびメソッドには適切な Type Hinting を記述すること 。


* 
**静的解析の厳格適用**: プロジェクトの `pyproject.toml` に定義された Ruff の Lint/Format ルール、および mypy の Strict モードに完全に準拠し、エラーが出ないコードを出力すること 。
